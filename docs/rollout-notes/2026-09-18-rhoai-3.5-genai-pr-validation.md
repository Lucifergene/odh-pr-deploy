# RHOAI 3.5 GenAI PR validation notes

## Scope

This records the environment-specific findings from validating the GenAI PR on
the Akundu RHOAI 3.5 cluster. It contains no credentials or Secret data.

## Deployment compatibility finding

Deploying only `odh-mod-arch-gen-ai` from an `odh-dashboard` PR caused the
GenAI Studio federated remote to fail at runtime (`TypeError: u is not a
function`). The release Dashboard host and the PR-built GenAI remote used
incompatible Module Federation runtime expectations.

The working deployment used the PR-built images for both:

- `RELATED_IMAGE_ODH_MOD_ARCH_GEN_AI_IMAGE`
- `RELATED_IMAGE_ODH_DASHBOARD_IMAGE`

Tool implication: a GenAI PR deployment must default to a paired GenAI and
Dashboard image stack resolved from the same PR SHA, with one atomic snapshot
and rollback transaction. A custom GenAI image must require an explicitly
provided companion Dashboard image.

## RHOAI 3.5 installer prerequisite finding

The `odh-dashboard-gen-ai` ClusterRole initially lacked the PGVector installer
permissions expected by the newer Playground flow. The rules added during
validation covered creation and named read/update/delete of the following
installer resources:

- core resources: Secrets, Services, PersistentVolumeClaims, ConfigMaps
- apps resources: Deployments
- networking.k8s.io resources: NetworkPolicies

During rollback, the restored RHOAI 3.5 operator reconciled these rules back
into the controller-owned ClusterRole. They are therefore its current declared
release state, rather than remaining manual drift. This still establishes the
tool boundary: it must detect and report missing prerequisites, rather than
silently modify cluster-wide RBAC.

## Fixture finding

An old unowned `llama-stack-config` ConfigMap remained after an earlier
OGXServer deletion and prevented a clean Playground recreation. Deleting that
orphaned ConfigMap and creating a fresh user-owned OGXServer resolved the
fixture state. The replacement OGXServer and all controller-owned resources
are intentionally preserved during this rollback because they are user test
resources, not tool-owned resources.

## Rollback performed

The rollback restores the original RHOAI 3.5 release image inputs:

- GenAI: `registry.redhat.io/rhoai/odh-mod-arch-gen-ai-rhel9@sha256:ead5e95700876ae178ae9850fd48ae5587accce387e3829a4bc3bfc6a86f7cae`
- Dashboard: `registry.redhat.io/rhoai/odh-dashboard-rhel9@sha256:eb7210f1b2290f556b6ae75b4ff236830a708fbc3486462e2525896238aea5c0`

It also removes the two `odh-pr-deploy.*` reconciliation annotations after
the operator has reconciled the restored values. Rollout status and workload
images must be verified after the change.
